# Dev Automation MCP Skill

## 定位

MCP 负责提供能力：飞书、网页、搜索、浏览器、实时文档、长期记忆、文件访问。

Skill 负责提供流程：先读上下文，再查资料，再实现，再测试，再多轮审核，最后沉淀错误和项目记忆。

## 触发场景

用户提出以下需求时使用本 Skill：

- 开始一个开发任务、修 Bug、重构、接入功能。
- 需要自动思考、分解任务、形成计划。
- 需要搜索资料、读取网页或读取飞书文档。
- 需要避免以前犯过的错误。
- 需要多轮审核项目、PR、当前变更或上线质量。
- 需要复盘会话并沉淀到项目记忆。

## MCP 使用策略

优先使用这些 MCP 能力：

- `sequential-thinking`：复杂任务拆解、方案权衡、多轮审核。
- 飞书/Lark MCP：读取飞书文档、知识库、会议记录、消息、日历。
- Search MCP：查询外部资料、版本变化、官方文档入口。
- Web reader/fetch MCP：读取指定 URL，提取证据。
- Playwright MCP：浏览器操作、页面检查、E2E 和视觉验证。
- Context7/库文档 MCP：查询框架、SDK、库的当前文档。
- Memory MCP：读取和写入跨会话的长期经验。

如果某个 MCP 不可用，明确说明缺失能力，并使用本地文件、网页搜索或用户提供资料作为降级方案。

## 开发任务流程

1. 读取项目 `CLAUDE.md`、`mistakes-ledger.md`、README、依赖文件、相关代码、相关测试和近期变更。
2. 明确目标、约束、风险、未知事实和验证方式。
3. 涉及飞书资料、网页、第三方库、API、权限、版本或不稳定事实时，先通过 MCP 查证。
4. 如果历史错误台账里有同类问题，写出本次规避规则。
5. 按现有项目风格做最小完整改动。
6. 运行最相关的测试、构建、lint、类型检查、浏览器验证或 API 调用。
7. 对重要改动执行多轮审核。

## 资料研究流程

1. 把问题拆成具体子问题。
2. 产品或团队问题优先查项目文件和飞书。
3. 技术和版本问题优先查官方文档、源码仓库、标准、SDK 文档。
4. 记录关键结论的来源、日期、版本和置信度。
5. 区分事实、推断和待确认项。
6. 输出可执行建议，不堆砌资料。

## 历史错误规避

每个项目维护 `mistakes-ledger.md`：

```markdown
# Mistakes Ledger

## Entries

### YYYY-MM-DD - 标题

- Context:
- Mistake:
- Root cause:
- Detection signal:
- Prevention rule:
- Verification next time:
```

开始任务前必须读取。出现误判、返工、漏测、配置错误、资料来源错误时追加记录。

## 多轮审核

至少执行五轮：

1. 需求一致性：是否解决真实目标，是否遗漏或过度实现。
2. 代码正确性：主路径、异常路径、边界、并发、状态、资源释放。
3. 数据与安全：鉴权、授权、输入校验、敏感信息、日志、迁移、回滚。
4. 测试与回归：覆盖风险、测试质量、构建和类型检查。
5. 交付质量：文档、配置、启动方式、可观测性、残余风险。

输出按严重程度排序，附带文件、行号或资料来源。除非用户只要求 review，否则先修复高严重问题。

## 会话复盘

完成重要任务后：

- 总结改动和验证结果。
- 标出未验证风险。
- 把可复用错误预防规则写入 `mistakes-ledger.md`。
- 只把长期有效的项目知识写入 `CLAUDE.md`。
