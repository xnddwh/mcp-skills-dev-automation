# 08 · 接下来往哪走

到这儿，你已经弄明白了 Agent 的循环、知道 MCP 和 Skill 的分工、搭起来过一个能用的、也把坑和最佳实践过了一遍。最后一章不教新东西，只回答一个问题：**然后呢？**

## 三个升级信号

别急着往上爬，先看看你该不该爬。出现下面任意一条，说明你到了该升级的时候：

1. **你开始需要查外部资料。** 改代码前要读飞书需求、要翻官方文档、要搜一下这个报错。本地文件不够用了。
2. **你开始需要「审核」这件事本身。** 不只是让它做，还要让它按固定的几轮标准挑自己毛病。
3. **你开始重复同一套流程。** 每次都要交代一遍「先读上下文、再改、再验证」，你烦了。

满足这些，本仓库的完整版就是你的下一站。

## 从三步到七步

`my-first-agent` 的三步循环，是 `dev-automation-mcp` 七步流程的**严格子集**。升级不是推倒重来，是长出来：

| my-first-agent（三步） | dev-automation-mcp（七步 + 五轮审核） |
|---|---|
| 说清楚 | 明确目标、约束、未知事实、验证命令 |
| 先读记忆 | 读 CLAUDE.md + 台账 + 代码 + 测试 |
| 做完记录 | 查证 → 最小改动 → 运行验证 → 多轮审核 → 复盘 |

多出来的核心是三样：**查证**（涉及外部事实必须先核实）、**验证**（改完必须跑测试或构建）、**审核**（重要改动至少过五轮标准）。

五轮审核我列在这儿，你以后会反复用到：需求一致性、代码正确性、数据与安全、测试与回归、交付质量。

升级时有个具体的衔接动作：你 `AGENT.md` 里攒的内容，直接并进 `CLAUDE.md` 就行，两者格式兼容。台账更是同一个文件，一个字都不用改。

## 一个真实的分歧：要不要用框架

写到这里，我必须把一个分歧摆在你面前，因为它直接决定你接下来学什么。

我把九份资料按这个问题的立场一分两派：

**一派说：直接上框架。** 推荐 LangChain、CrewAI、LangGraph，理由是它们省掉大量重复劳动，社区大、文档全，别重复造轮子。有资料甚至直接给了「新手该用哪个框架」的答案。

**另一派说：先手写一遍那个循环。** Amanai Lab 和 TheAI 學院都持这个立场，后者的原话是「初學建議先手刻一次以理解流程」。理由也很硬：那个核心循环简单到可以用任何语言手写，你手写过一遍，再用框架才知道框架替你做了什么、在哪儿可能坑你。

我不替你选，但给你我的判断和它的适用条件：

- 如果你现在的目标是**尽快做出一件能用的东西**，而且你对编程本身还不够熟 → 用框架，省时间。
- 如果你是想**真正搞懂 agent 是怎么回事**，或者你以后要长期做这件事 → 先手写一遍那个几十行的循环。第 02 章给你的那段伪代码，用你熟悉的语言实现一遍，接两个最简单的工具跑通，这一步的收益能抵得上十篇教程。

我的倾向偏后者。因为你手写过之后，框架对你就不再是黑盒，而是一个「我知道它在哪省了事」的工具。但如果你这周就想交东西，别听我的，先用框架把事办成。

## 多 agent 什么时候才值得

第 06 章说过别急着上多 agent。那什么时候**该**上？

只有两种情况，而且都是从单 agent 那里**真实撞到墙**才成立的：

- **任务长到一个上下文窗口装不下。** 那就拆成 planner 负责拆解、worker 负责执行。
- **需要两个独立视角互相审。** 一个写、一个挑刺，比一个既写又审更靠谱。

除了这两条，其它的「多 agent」多半是架构好看而已。先单后多，这个顺序别倒。

## 这个仓库还能往哪长

如果你打算继续用这套东西，本仓库的 `docs/ROADMAP.md` 里列了后面的方向，我不重复了。挑三个我觉得最有价值的说一下：

- **专项 skill。** 把高频场景拆出来，比如 `systematic-debugging`（复杂 bug 排查）、`release-check`（上线前检查）。每个保持短小，细节塞进 `references/`。
- **项目知识库。** 让 `docs/adr/`（架构决策）、`runbooks/`（故障处理）这些慢慢攒起来。项目做得越久，这些越值钱。
- **自动化治理。** 用 hooks 在每次编辑后自动跑轻量检查，用 CI 卡住文档和测试。目标是流程不靠记忆，靠机制。

## 最后想跟你说的

Agent 这个东西，被说得神乎其神，但它的本体朴素得有点扫兴：**一个会调用工具的循环，加上清楚的规则和防护**。

真正难的从来不是那个循环——那段伪代码你十分钟就能敲出来。难的是**让它可靠**：边界划清楚、错误看得见、成本控得住、踩过的坑真的记住。

这份耐心，才是新手区到进阶区之间那道真正的门槛。工具会换，框架会过时，这件事不会。
