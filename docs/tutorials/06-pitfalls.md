# 06 · 新手常踩的坑

这一章的内容，是我把九份入门资料里「常见错误」那几节全部摊开、去掉重复之后剩下的东西。有意思的是，不同作者、不同平台、甚至不同语言，列出来的坑高度重合——说明这些不是某篇文章的偏见，是大家真金白银踩出来的。

每个坑我按同一个格式写：**你会看到什么现象 → 为什么会这样 → 该怎么改**。建议你边做边对照。

## 坑 1：一上来就塞太多工具

**现象。** 你把能装的 MCP 全装了，十个工具挂上去，结果 agent 开始乱调——明明该搜网页，它去查了数据库。

**为什么。** 每个工具都会占上下文，也都会增加一个「选错」的机会。工具越多，模型在「该用哪个」这一步上出错的概率越高。有个资料给了个具体阈值：单 agent 的工具超过 5 个，可靠性会明显下滑，超过 10 个就该考虑拆了。

**怎么改。** 从一个工具开始，跑通，再加第二个。加新工具的唯一理由是：**它的缺席已经成了瓶颈**，而不是「反正装上也不亏」。

## 坑 2：指令写得太模糊

**现象。** 你让它「帮我优化一下这个页面」，它改了一堆你根本没让它碰的东西。

**为什么。** 模型只能按你给的信息去猜。它不知道你的优先级、不知道什么算「优化完了」、更不知道你不想让它动哪些部分。

**怎么改。** 把它当成第一天上班的新同事来交代。Tech With Sanjay 那篇的类比值得抄下来：**角色、目标、输出格式、不确定时怎么办、绝对不能做什么**，这五样说全。对比一下：

- 差：「优化登录页」
- 好：「优化登录页的移动端提交按钮。目标：点击后能正常提交。只改这一个按钮相关的代码，不要动其他样式。如果发现原因不在前端，停下来告诉我，别自己改后端。」

## 坑 3：没有停止条件

**现象。** 你走开十分钟，回来发现账单多了几块钱，日志里同一个工具被调了三十遍。

**为什么。** 第 02 章讲过，模型如果不觉得任务完成，就会一直循环。它不知道「够好了」，它只知道「还没完」。

**怎么改。** 三层至少配两层：模型自己判断 + 步数上限（比如 15）+ 成本或时间上限。LearnAI 那篇的建议很具体——直接在系统提示里写「任务完成后写出结果并结束」。

## 坑 4：只看结果，不看过程

**现象。** agent 说「已修复」，你信了，过两天发现它只是把报错掩盖了。

**为什么。** 最终输出是结果，**过程才是真相**。Amanai Lab 说得直白：调试时最有效的办法，是把每一轮的「模型输入、模型输出、工具调用、工具结果」全打出来。只看结局，你根本不知道它哪一步开始跑偏。

**怎么改。** 从第一版就留日志。别等出事了再加——你不能调试你看不见的东西（几个来源都把「没有可观测性」单独列成一个坑）。

## 坑 5：给不可逆操作开了绿灯

**现象。** 你让它整理一下邮箱，它顺手删了三封它认为「不重要」的邮件。

**为什么。** 你把「能读」和「能删」给了同一个工具，它就默认都能用。

**怎么改。** 从**只读**开始。搜索、读取、分析这类错了也只是白忙一场，可以放它跑。发消息、付款、删数据这类收不回来的，一律加人工确认。所有资料在这点上口径完全一致，我一次反例都没找到。

## 坑 6：还没有需求就上多 agent

**现象。** 你照着某个教程搭了个 planner + worker + reviewer 的三 agent 系统，然后花一个礼拜调它们之间怎么传话，核心任务还是没跑通。

**为什么。** 单个 agent 更快搭、更好调、更好管。多 agent 是真有了协调难题才需要的解药——比如任务长到一个上下文窗口装不下，或者确实需要两个独立视角互相审。不是你遇到的所有问题都配得上它。

**怎么改。** 先用一个 agent 把任务跑可靠。**只有当单个 agent 因为某个具体原因做不到时**，再拆。别为了架构好看而拆。

## 坑 7：把 demo 当成了可靠

**现象。** 演示的时候惊艳全场，真用起来一塌糊涂——换一个刁钻点的输入就崩。

**为什么。** 你测的是一个理想输入。但真实世界里，输入经常是残缺的、矛盾的、甚至带恶意的。

**怎么改。** 上线前用**真实场景 + 刁钻输入**测。有个资料说得狠但很对：「我测的时候是好的」不是测试策略。至少准备一批可重复跑的场景，覆盖正常、边界、空白、对抗这几类。

## 坑 8：不看成本

**现象。** 月底账单出来，比你预期多了十倍。

**为什么。** 每一次模型调用、每一次工具调用、每一份塞回上下文的检索结果，都在花钱。新手做 demo 时基本不看这个数。

**怎么改。** 从第一天就盯。设死预算上限，记录每个任务大概花多少 token。顺便说一个能省大钱的思路：**简单活交给便宜快的模型，复杂推理才用贵的**，有资料说这么分层能省掉一大半开销。

## 坑 9：给运行中的 agent 动结构

**现象。** 你一边加工具一边改提示词，然后发现它彻底不听话了。

**为什么。** 一次只改一个变量，你才知道是哪个改动导致的。同时动好几处，出了问题你只能靠猜。

**怎么改。** 改动要能回退，一次改一处，改完立刻用同一批测试场景跑一遍。这条不是资料里专门列出来的，是我自己做东西的教训，加在这儿。

## 坑 10：自动化一个本来就乱的流程

**现象。** 你把一个手工做的、自己都嫌麻烦的流程交给 agent，结果它更快地制造了一堆错误。

**为什么。** AI 不会自动修好一个设计得烂的流程。它只会把你那个乱流程**更快地**执行一遍。AI Discoveries 那篇的话我原样引用：先简化流程，再自动化。

**怎么改。** 动手写 agent 之前，先用纸把流程顺一遍。你自己都讲不清楚的步骤，别指望模型能替你理清。

## 如果只记三条

坑有十个，但真要说最要命的，是这三个：

1. **工具别贪多** —— 超过 5 个就该警惕了
2. **不可逆操作必须有人把关** —— 这条没有例外
3. **过程要看得见** —— 没有日志，你就是在盲修

剩下七个，都是这三条的自然推论。

---

**动手：** 拿你上一章做出来的那个 agent，对着这十条逐条过一遍。大部分现在还不适用（因为你的 agent 还很弱），但把它当一张清单留着，等你工具越加越多的时候回来查。
