# 04 · 搭出你的第一个 Agent

前三章是看懂，这一章是动手。你要在 15 分钟内，跑起来一个真的属于你自己的 agent。

🖐️ **这一章整章都必须亲手做。** 原理可以读，但「装 skill、重启客户端、看它跑起来」这件事没有任何替代路径。AI 能替你写说明，替不了你按下回车。卡住别慌，文末「你大概率会卡在哪儿」就是为你准备的。

先说清楚这一章**不做**什么：不装框架、不配 MCP、不写一行模型调用代码。原因很简单——你现在的目标不是「搭一套系统」，是**先让那个循环在你手里转起来一次**。转过一次，后面才有得谈。

## 你会得到什么

跑完之后，你的项目目录里会多出三个文件：

```
你的项目/
├── AGENT.md            # 你的 agent 说明书：你是谁、目标、规则、常用命令
├── mistakes-ledger.md  # 错误台账：踩过的坑记这儿
└── first-tasks.md      # 第一周的三个练习任务
```

加上一个装进 agent 客户端的 skill。就这些，没有别的。

## 第 1 步：生成你的三个文件

本仓库自带一个零依赖的引导脚本，只用 Python 标准库。打开终端，把下面这行的 `<你的项目目录>` 换成你自己的路径：

```bash
python skills/my-first-agent/scripts/setup_my_agent.py <你的项目目录>
```

它会问你四个问题。每个问题都可以直接回车用默认值，我给「不知道填什么」的人留了退路：

| 它会问 | 默认值 |
|---|---|
| 怎么称呼你？ | 新手 |
| 你最近在做什么方向的事？ | 学习编程 |
| 常用语言或工具？ | Python |
| 最想先让 agent 帮你做什么？ | 解释代码 |

不想被打断的话，也可以一口气把答案传进去：

```bash
python skills/my-first-agent/scripts/setup_my_agent.py ./我的项目 --answers "小王" "做个人网站" "JS + VS Code" "改小bug"
```

脚本有个我特意加的性格：**它不覆盖你已经有的文件**。第一次跑生成三个文件，第二次跑它会说「已存在，跳过」。想重来就显式加 `--force`。写过脚本的人都知道，「手一抖把用户文件覆盖了」是多招人恨的行为。

## 第 2 步：检查生成的东西

打开 `AGENT.md`，就三块：

- **我是谁** —— 刚才四个答案填进来的一小段
- **给 agent 的三条规则** —— 已经写好，新手版
- **常用命令** —— 目前是空的，等着你在做的过程中一条条填

那份 `mistakes-ledger.md` 是从仓库根目录的 `templates/` 直接复制过来的，格式和完整版的 `dev-automation-mcp` 用的是**同一份**。这一点是故意的，后面你会看到好处。

## 第 3 步：把 skill 装到你用的工具里

把 `skills/my-first-agent/` 整个文件夹，复制到你所用 agent 的 skills 目录。落点各工具不太一样：

| 你用的工具 | 放哪儿 |
|---|---|
| Claude Code | `~/.claude/skills/` |
| Codex | `~/.codex/skills/` |
| Hermes | `~/.hermes/skills/` |
| Codex / Gemini / Copilot / OpenCode | `~/.agents/skills/`（共享目录） |

嫌手动复制麻烦，用统一定位安装器也行，一条命令装到所有已安装的 agent：

```bash
npx skills add xnddwh/rookie-agent-guide --skill my-first-agent -g -a '*'
```

**装完记得重启你的 agent 客户端。** 这是新手第一大「装完没反应」的原因——skill 只在客户端启动那一刻被发现一次，热装是无效的。

## 第 4 步：让它做第一件事

在你项目的目录下，对 agent 说这么一句：

```
使用 my-first-agent，完成 first-tasks.md 里的任务 1
```

然后看它做。任务 1 是「只看不改」——让它解释一个文件的作用，你不必担心它乱动东西。这是刻意的设计：**新手第一次，先建立信任，再给它动手的权限。**

## 那个三步循环

`my-first-agent` 的全部精髓就是这三步，我把它单独拎出来，因为你要在之后每一次任务里重复它：

```
第 1 步  说清楚      我要做什么 + 什么算做完
第 2 步  先读记忆    agent 先看 AGENT.md 和 mistakes-ledger.md 再动手
第 3 步  做完记录    做成了写进「常用命令」，做错了写进错误台账
```

第 2 步是很多人会跳过、但性价比最高的一步。你想想：一个每次开工前都会先翻一遍「上次我在这个项目里栽过哪些跟头」的助手，和一个什么都不记得的助手，你更信哪个？

## 你大概率会卡在哪儿

我先把几个必然会遇到的坑摊开，省得你到处搜：

**装完一点反应没有。** 九成是没重启客户端。剩下一成是目录名和 `SKILL.md` 里的 `name` 对不上——这两个必须一字不差。

**它不按三步循环来。** 检查你有没有把 skill 真的放进它的 skills 目录。放对了但没触发，就把话说全一点：「使用 my-first-agent 这个技能」。

**`AGENT.md` 和 `CLAUDE.md` 到底谁是谁。** `AGENT.md` 是我起的通用名，工具无关；Claude Code 默认读 `CLAUDE.md`。你以后要是升级到完整版，把 `AGENT.md` 的内容并进 `CLAUDE.md` 就行，两者格式是兼容的，这也是我为什么敢让你从通用名起步。

**脚本报找不到模板。** `setup_my_agent.py` 会从自己所在位置一路往上找仓库根目录里的 `templates/`。如果你把脚本单独抠出来、脱离了仓库结构，它就找不到，会提示你手动从 `templates/` 复制。

## 现在你已经会的

回头看看，你其实已经把第 02 章那个循环用了一遍，只是用工具的形式：**读上下文（想）→ 干活（做）→ 记录（看）**。你做的这个 agent 简单，但它不是玩具——它就是那个循环最朴素的形态，只不过「想」的那部分交给了模型，「做」的那部分暂时只有读写文件。

`first-tasks.md` 里还有两个任务等着你，建议这周内做完：

- **任务 2（小改动）** —— 做一个 5 分钟能完成的小修改，改动前后各跑一次验证命令，把命令记进 `AGENT.md`
- **任务 3（踩坑记录）** —— 故意问一个它会答错的问题，然后写进错误台账

任务 3 是三个里最重要的。别跳过它。**主动去踩一个坑并记下来**，是你从「用 AI」变成「会跟 AI 协作」的分水岭。

---

🔬 **跑完自己验这三件事（别信它自己说完成了）：**

1. 三个文件真的生成了吗？打开看一眼，别只看它打出 `[write]`。
2. skill 复制进 skills 目录并**重启**客户端后，问它一句「你能看到 my-first-agent 这个 skill 吗」。答得出来说明装上了。
3. 让它做任务 1，然后你**抽查**它解释的那个文件——它说的和实际代码对得上吗？

这三步 AI 都替不了你。它是当事者，你是验收人。

**动手：** 就是这一整章。别读完就走，现在去终端敲那行命令。
