# 常见问题

都是我自己做的时候卡过的，或者别的资料里反复被问到的。按「装/用/懂」三类分。

## 装

**装完一点反应都没有，叫它也不理我。**

九成是没重启客户端。skill 只在启动那一刻被发现一次，装完必须重开。

剩下一成，检查文件夹名和 `SKILL.md` 里 `name` 那行是不是**完全一致**。差一个字符都认不出来。

**我有好几个 agent（Claude Code、Codex、Hermes），要装好几遍吗？**

用 `npx skills add ... -a '*'` 一次装完。它默认用软链接，几个 agent 指向同一份源文件，你以后改一处，所有地方都跟着变。

**skill 和 MCP 我必须都装吗？**

不用。`my-first-agent` 零依赖，纯靠读写文件就能跑。MCP 是等你确实需要「够到外部」（联网、飞书、浏览器）时才加。

**Windows 上 `~` 是哪个目录？**

就是你的用户目录，比如 `C:\Users\你的名字\`。文档里写 `~/.claude/skills/` 就是 `C:\Users\你的名字\.claude\skills\`。

## 用

**`AGENT.md` 和 `CLAUDE.md` 是什么关系？**

`AGENT.md` 是我起的通用名，不绑定任何工具。Claude Code 默认只读 `CLAUDE.md`。

所以升级到完整版 `dev-automation-mcp` 的时候，把 `AGENT.md` 的内容并进 `CLAUDE.md` 就行。两者格式是兼容的——这也是我敢让你从通用名起步的原因，以后不用推倒重来。

**它老是不按三步循环走怎么办？**

先确认 skill 真的进了它的 skills 目录。放对了还是不行，就把话说明白点：「使用 my-first-agent 这个技能，先读 AGENT.md」。

大部分时候不是它不听话，是你给的触发词太模糊，它没意识到该用这个 skill。

**我该先做哪个任务？**

按 `first-tasks.md` 的顺序来。任务 1 是**只看不改**（让它解释一个文件），建立信任；任务 2 做个小改动；任务 3 故意让它答错一次，然后记进台账。

任务 3 最容易跳过，但它是三个里最重要的。主动踩一次坑、把根因挖出来，是你从「用 AI」变成「跟 AI 协作」的分界线。

**它会不会改坏我的文件？**

`my-first-agent` 的规则里有「不确定就问，不要猜」，而且你的第一个任务是只看不改。但说到底，模型是有概率犯错的，**做重要的事之前先备份**。这不是不信任它，是基本常识。

## 懂

**Agent 和聊天机器人到底差在哪？**

差别只有一个：**会不会自己动手、自己决定下一步**。聊天机器人只输出文字；agent 会为了一个目标去调工具、改东西、看结果、再决定。详见[教程 01](./tutorials/01-what-is-an-agent.md)。

**MCP 和 Skill 是一回事吗？**

不是，而且是两个层次的事。MCP 负责「够不够得到」，Skill 负责「做得好不好」。它俩分工，不是二选一。详见[教程 03](./tutorials/03-mcp-and-skills.md)。

**我一定要会编程吗？**

看你要做什么。只想用起来（跑脚本、装 skill、按台账记录），会复制粘贴命令就够了。想手写那个循环、加自己的工具，那得会点编程。有资料说得很实在：真正的技能不是会调 API，而是会围绕 AI 设计可靠的流程——这件事本身，跟写不写代码是两回事。

**为什么我的 agent 会突然忘记前面说的话？**

不是它「忘」，是**上下文满了**。所有东西都挤在一个有限的窗口里：任务、工具清单、历史对话、工具返回的一大坨结果。跑几轮，早期信息就被挤出去了。

解法是压缩：老对话压成摘要，工具返回的砍到重点再塞回去。详见[教程 02](./tutorials/02-how-agent-works.md)。

**为什么资料里说的模型版本跟我不一样？**

因为这类东西半年就更新一轮。我在教程里刻意**不写具体模型版本**，只给判断方法——因为写进去只会很快过期，反而误导你。你要选型的时候，去看官方文档当下的说法。

**我要不要一开始就搭多 agent？**

不要。单 agent 更快搭、更好调、更好管。只有当你真实撞到墙了——任务长到一个上下文装不下，或者确实需要两个独立视角互审——才值得拆。详见[教程 08](./tutorials/08-level-up.md)。

## 这个仓库本身

**我可以拿去自己用、自己改吗？**

可以。MIT 许可证，个人用、改、再发布都没问题，只要保留许可证文件。详见 `LICENSE`。

**我自己做的东西能放进这个仓库吗？**

这是给你的个人工作流仓库，本来就是你自己的。建议按 `skills/<你的skill名>/SKILL.md` 的格式加，保持和现有两个 skill 一致，这样 `npx skills` 也能认。

**装第三方 skill 安全吗？**

不一定，得看。社区出现过投毒案例，恶意指令藏在 skill 里能让你中招。装之前把它的 `SKILL.md` 读一遍、`scripts/` 扫一眼，看不懂就先别装。详见 `SECURITY.md`。
