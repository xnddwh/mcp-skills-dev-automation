# 提示词优化规范（Prompt Playbook）

> **本文件是提示词的组织与使用规范，独立于任何单个项目。**
> 适用对象：在 Hermes / WorkBuddy / Claude Code / Codex 等 agent 工具中的日常使用。
> 配套教程：[`../docs/tutorials/`](../docs/tutorials/)（八章，讲"为什么"）—— 本文讲"怎么系统化地组织"。
> 模板库：[`templates/`](./templates/) ｜ 口令表：[`口令表.md`](./口令表.md) ｜ 台账：[`mistakes-ledger.md`](./mistakes-ledger.md)。
> 最后更新：2026-10-11 ｜ 真源：本文。

---

## 0 · 一分钟速查

| 场景 | 用什么 | 一句话 |
|---|---|---|
| 首次做某类任务 | **A 型 · 冻结单** | 背景+目标+验收+禁止，先让它问答疑点再动手 |
| 每天重复的活 | **B 型 · 例行单** | 存成模板，一句话触发 |
| 已定义好流程 | **C 型 · 口令单** | `<口令> + 参数`，由 skill 承载 |
| 排查问题 | **D 型 · 诊断单** | 现象+已知+排查顺序，要求指到具体行 |
| 建新能力/新流程 | **E 型 · 建卡单** | 用户合书复述 → AI 核 → 落 skill |
| 复盘回顾 | **F 型 · 结算单** | 数据说话，产出下一周期唯一首选 |

**三条铁律**：① 没写验收 = 没下任务 ② 没写禁止 = 它什么都敢做 ③ "做完了"不算数，看文件系统。

## 1 · 当前问题诊断

> 诊断依据：Hermes 实测配置（`AppData/Local/hermes/config.yaml`）、会话审计日志（`.workbuddy/audit-log/*.jsonl`）、kaoy 项目实战记录、`rookie-agent-guide` 教程现状。

### 1.1 五个已证实的问题

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| **P1** | **提示词散落，无统一入口** | 教程在 `docs/tutorials/`、模板散落各处、实践在项目 skill 里（单文件上千行）| 同一件事三处写法，用时想不起来去哪个 |
| **P2** | **"验收"意识只在部分场景生效** | 教程阶段二讲了三件套；但实际会话中大量任务只给目标不给验收 | AI 猜范围，返工 |
| **P3** | **重复劳动没有模板化** | 用户自述"使用比较杂乱"；audit-log 显示同类任务反复重写指令 | 每天重建轮子 |
| **P4** | **教训留在会话里，没回流** | 上次核对发现"重试走安全档"只写在提交信息、没进 skill | 换会话必重踩 |
| **P5** | **配置层与使用层脱节** | 有 17 个开发类 skill，但没串成流水线；`delegation` 模型未钉（烧 token） | 能力闲置 + 成本失控 |

### 1.2 根因：缺"中间层"

```
现状：  零散提示词 ──→ 直接执行 ──→ 结果（好/坏靠运气）
                    ↑ 教训留在会话里，不回流

应然：  零散提示词 ──→ 【分类 + 模板化】 ──→ 执行 ──→ 结果
                              ↑______________________|
                              教训回流到模板/台账
```

**你现在缺的不是"更多提示词技巧"，而是把散落的东西分类、命名、存盘的中间层。** 教程提供了"心法"（任务三件套），但没提供"兵器架"（分类与模板库）。

### 1.3 与教程的落差对照

| 教程已讲 | 但你没做到 | 本文补什么 |
|---|---|---|
| 任务三件套（背景/目标/验收） | 只在少数场景用 | → 扩展为 **A 型冻结单**，加"禁止"和"先问答疑点" |
| 错误台账 | 台账在仓库里，日常不用 | → 提出**最小台账**（3 字段），降低启用门槛 |
| 写技艺说明书（skill） | 会写但触发时机不清 | → **E 型建卡单**，明确"什么时候该建" |
| 换工具也不丢 | 但没做跨工具同步 | → 端到端流程第 7 步：单一真源 + symlink |

## 2 · 优化目标与原则

### 2.1 目标（可验收）

| 目标 | 判据 |
|---|---|
| **不再重复写同类指令** | 高频任务的模板化率 ≥ 80% |
| **返工率下降** | 同类任务返工 ≤ 1 次 |
| **教训不重踩** | 出错后 24h 内，防复发规则已落台账或 skill |
| **成本可控** | 子代理（机械活）token 占比可见，机械活不下沉到主模型 |

### 2.2 五条原则

1. **减少猜测**（教程原话）：写的越全，AI 猜错的空间越小。这是所有技巧的唯一本质。
2. **验收前移**：验收标准写在开工前，不是做完再挑毛病。
3. **模板 > 记忆**：模板存在文件里，不靠你记；能复用就别重写。
4. **教训必回流**：每次返工都是一条待落盘的规则，不许只留在对话里。
5. **分层用力**：简单活给便宜模型/子代理，复杂推理才用主模型。

### 2.3 三条禁忌（vs 误区）

| 误区 | 纠正 |
|---|---|
| 追求"咒语式"提示词 | 没有咒语。本质是把背景/约束/格式说清 |
| 一次给巨长需求 | 超长需求会被上下文腐化稀释 → 先冻结范围，分批做 |
| 靠"我记住就行" | 记忆会随会话变长被冲淡 → 写进文件 |

## 3 · 提示词分类与模板规范

> **六类**：A 冻结单 / B 例行单 / C 口令单 / D 诊断单 / E 建卡单 / F 结算单。
> 命名规则：`<类型字母>-<用途>-<可选版本>`，存到模板库（见 §5.3）。

### A 型 · 冻结单（新任务首次执行）

**用途**：任何需要动手改东西的首次任务。**这是最核心的一类。**

```
【任务冻结】
目标：<一句话，可验收>
背景：<我是谁/这是什么项目/关键约束>
允许改：<文件或目录清单>
禁止：<git / 删文件 / 装依赖 / 改接口 / 其他>
验收：<可执行判据，如 "run_tests.py 全绿" 或 "清单行数=文件数">
不确定的点：<列出，先只回答这些，别动手>
```

**规范要点**：
- **"不确定的点"必须是最后一行**——强制 AI 先暴露疑问，再批准执行。这一条能拦掉大部分返工。
- **禁止项永远要写**。教程原话："凡是'不要自己决定''不要删东西'这类约束，你写了它才会遵守。"
- 冻结单没产出，不许进入执行。

**反例 → 正例**：
- ✗ `帮我整理一下这个文件夹`
- ✓ 见上（背景/目标/验收/禁止齐全）

---

### B 型 · 例行单（重复任务）

**用途**：每周/每天重复做的事。**从 A 型沉淀而来。**

```
【<任务名> · 例行】
按 <上一次的模板/流程文件> 执行本周 <任务>。
本次输入：<本周的新数据/变更>
差异点：<与上次不同的地方，没有就写"无">
照旧验收：<上一版的验收标准>
```

**规范要点**：
- 第一次用 A 型做，做完**立刻把 A 型存成 B 型模板**（这是模板化的动作）。
- 第二次起只说"按上次流程"，附本次差异。

**已沉淀的 B 型（示例，按你实际补全）**：
- `B-周报`、`B-行业新闻整理`、`B-错题批改`、`B-测试上传`

---

### C 型 · 口令单（已流程化的能力）

**用途**：已经写成 skill 的流程，一句话触发。

```
<口令> <参数>
```

**规范要点**：
- 口令要**短、可区分、不撞车**。你已有的：`/kaoy-daily`、`复盘阅读`、`批改作文`。
- 口令必须对应一个真实存在的 skill / 文件，否则就是空口令。
- **建口令的时机**：同一件事做过 3 次以上（教程判据）→ 立刻固化成 skill + 口令。

**口令清单（建议集中登记）**：见 §5.3 模板库的 `口令表.md`。

---

### D 型 · 诊断单（排错）

**用途**：现象出现、需要定位根因。**对应系统化调试四阶段。**

```
【诊断】
现象：<用户可见的症状>
已知：<服务在跑/日志无 ERROR/何时开始>
已排除：<试过什么，不管用>
请按序排查：(1) 异常是否被静默吞掉 (2) 类型问题 (3) 环境变量不继承 (4) 缓存与新数据错位
要求：结论必须指到 <文件:行>；每步先给"怎么验证"再给结论。
```

**规范要点**：
- **"已排除"很重要**——避免 AI 重复你走过的死路。
- 排查顺序是**你踩过的坑的顺序**（静默失败四步），可复用。
- 硬要求：**结论必须指到具体一行**（不能指到行的结论，前提未验证）。

---

### E 型 · 建卡单（沉淀能力）

**用途**：把做过的事变成可复用能力（skill / 台账条目）。

```
【建卡】
素材：<本次做的事 / 用户的合书复述>
落点：<skill Always-on 规则 / 坑列表 / references/ 主题文件>
分类要求：① 规章级 → Always-on ② 具体坑 → 现象+根因+判据 ③ 状态 → 项目状态文件
禁止：把只写在提交信息里的结论当作已落盘。
```

**规范要点**：
- 用户的原始规矩是"用户合书复述 → AI 核 → 用户迁移"（名字用户起）。
- 此单为**规范分析场景**专用（不必套用 kaoy 项目的建卡三步）。

---

### F 型 · 结算单（复盘）

**用途**：周期收尾，产出下一周期唯一首选。

```
【结算 · <周期>】
已完成：<逐项列，标证据等级>
未完成：<原因，是否阻塞>
数据：<关键指标：通过数/耗时/成本>
教训：<本次返工点 → 防复发规则>
下一周期唯一首选：<一件事>
```

**规范要点**：
- **用数据说话**，不用"感觉不错"。
- 教训必须落到 §4.4 的回流动作。
- 只给**一个**下一周期首选，不给菜单。

## 4 · 使用流程与最佳实践

### 4.1 主线流程（七步）

```
① 选型    判断任务属于 A-F 哪一类 → 取对应模板
② 填单    填模板（A 型必填"不确定的点"）
③ 执行    AI 先问答疑点 → 你批准 → 才动手
④ 验收    按验收判据核对（抽检/数数/看文件系统）
⑤ 定损    失败 → 判定是"模板问题"还是"执行问题"
⑥ 回流    教训写进台账/模板（这一步最常漏）
⑦ 升级    同类做 3 次 → 升为 C 型（skill + 口令）
```

**关键约束**：②→④ 不许跳；**⑥ 是全流程最容易漏、价值最高的一步**。

### 4.2 上下文管理（对治腐化）

- **任务没变、对话太长** → 让它把有效内容压成状态（目标/已完成/约束/下一步）继续。
- **任务变了、旧对话堆满错误** → **开新会话**，只带走阶段性总结。
- 重要要求**写在开头或结尾重申**（中间最易被忽略）。

### 4.3 六个最佳实践

1. **先给验收再给任务**——验收是约束，不是事后检查。
2. **结构化输出**——要 JSON/表格就明说，减少解析错。
3. **事实与推断分开**——让它标"待确认"，别让它编。
4. **一次不超过 10 个对象**（教程台账教训：30 个文件时它"累了"）。
5. **危险操作先列计划**——不可逆的事保留你的确认权。
6. **一条指令只干一件事**——合并任务会互相污染。

### 4.4 教训回流规则（§4.1 第⑥步的操作手册）

每次返工，问三个问题并写下来：

```
① 这是不是重复犯的错？  → 是 → 已有条目，追加一例即可
② 防复发该写在哪？       → 纪律 → skill Always-on；具体坑 → 坑列表
③ 明天怎么验证它生效？   → 写一条可执行判据
```

落点分层：

| 内容 | 落点 |
|---|---|
| 跨会话纪律 | skill 的 Always-on 规则 |
| 一次性坑（现象/根因/判据） | skill 坑列表 或 `references/<主题>.md` |
| 项目状态 | 项目内的状态文件（**不写 memory**，会溢出） |
| 用户偏好 | 用户画像文件（精炼，限 500 字级） |

## 5 · 如何整合现有新手入门教程

### 5.1 两者关系（互补，不重复）

| | 教程（[`../docs/tutorials/`](../docs/tutorials/)） | 本规范 |
|---|---|---|
| 定位 | **心法**：为什么这么做 | **兵器架**：具体怎么组织 |
| 结构 | 五阶段递进（聊天→下任务→跑腿→记忆→固化） | 六类模板 + 七步流程 |
| 读者 | 从零开始的人 | 已经在用、但用得乱的人 |
| 判据 | 阶段自测（闭卷） | 指标表（§7） |

**一句话**：教程教你"下任务要带背景+目标+验收"；本规范告诉你"这就是 A 型冻结单，存到模板库第 1 格，同类做 3 次升 C 型"。

### 5.2 逐阶段映射（教程 → 本规范）

| 教程阶段 | 教程教了什么 | 本规范对应 |
|---|---|---|
| 阶段一 先聊起来 | 直接对话、指出坑 | 无模板，保留即兴 |
| **阶段二 下任务** | 任务三件套 | **→ A 型冻结单**（加"禁止"+"不确定的点"） |
| 阶段三 让它跑腿 | 🔬验收、上下文腐化、改建议为命令 | **→ 验收判据 + §4.2 上下文管理 + D 型** |
| 阶段四 教它记住你 | CLAUDE.md + 错误台账 | **→ §4.4 回流规则 + 最小台账** |
| 阶段五 固化流程 | 写技能说明书（skill） | **→ C 型口令单 + §4.1 第⑦步升级** |
| 速查三张便签 | 下任务/验收/出错时 | **→ §0 一分钟速查** |

### 5.3 建议的目录结构（模板库）

在教程仓库（`rookie-agent-guide`）里增加一层**模板库**，让教程"可执行化"：

```
docs/tutorials/               ← 现有八章（心法，不动）
prompt-playbook/              ← 新增：本规范落地处（兵器架）
├── README.md                 ← 本文（或指向本文）
├── templates/
│   ├── A-冻结单.md
│   ├── B-例行单.md
│   ├── C-口令单.md
│   ├── D-诊断单.md
│   ├── E-建卡单.md
│   └── F-结算单.md
├── 口令表.md                 ← 集中登记所有 C 型口令
└── mistakes-ledger.md        ← 复用现有台账模板，补"最小三字段"版
```

**最小台账版**（降低启用门槛，3 字段即可）：

```
### YYYY-MM-DD  <一句话标题>
- 错在哪：<具体>
- 下次怎么防：<一条规则>          ← 最重要，必须能明天用上
- 怎么验证：<可执行判据>
```

> 教程的台账有 6 字段，太重；日常用 3 字段，重要错误再补全 6 字段。

### 5.4 教程的什么要保留、什么要升级

| 教程内容 | 处置 |
|---|---|
| "任务三件套"提法 | **保留**（已深入人心），在本规范中标注为 A 型的简化版 |
| 三种标记（🖐️/🔬/✅） | **保留**，本规范的模板也可沿用标记 |
| 五阶段结构 | **保留**（叙事好），本规范作为其"第 6 阶段：系统化" |
| "写完存到备忘录" | **升级**为"存到模板库 `prompt-playbook/templates/`" |
| 错误台账 6 字段 | **升级**：日常用 3 字段最小版 |

## 6 · 可落地执行步骤

### 第一周：建架子（不改变习惯）

1. **建目录**：在 `rookie-agent-guide` 仓库创建 `prompt-playbook/` 及 `templates/`。
2. **抄落模板**：把 §3 的六个模板各存成一个文件（A–F）。
3. **建口令表**：新建 `口令表.md`，先登记已有的 3 个（`/kaoy-daily`、`复盘阅读`、`批改作文`）。
4. **建最小台账**：用 §5.3 的 3 字段版，把最近 3 次返工补录进去。

### 第二周：用起来（只用一个模板）

5. **只用 A 型**：本周所有动手任务，一律先写冻结单。**重点是养成"先写验收"的习惯。**
6. **每日一条**：每次返工，当场往台账加一条 3 字段记录。
7. **周末结算**：用 F 型做一次周结算，数一下"这周有几条台账条目变成了规则"。

### 第三周：沉淀（开始回收）

8. **挑一个高频任务**做成 B 型模板（选你做过最多次的）。
9. **同类做满 3 次的**，升级为 C 型（skill + 口令），登记进口令表。
10. **回到 §7 量一次指标**，对比第一周。

### 之后：维护

- **每月**：清理台账，把同主题条目合并；检查口令表有没有失效口令。
- **每季度**：把重复 3 次的 B 型升 C 型；把过时模板删掉。

## 7 · 评估改进效果的方法

### 7.1 五项指标

| 指标 | 怎么量 | 目标 | 频率 |
|---|---|---|---|
| **模板化率** | 高频任务中，用模板的占比 | ≥ 80% | 每周 |
| **返工率** | 同一任务重新打开次数 | ≤ 1 次/任务 | 每次 |
| **回流及时率** | 出错 → 台账/规则落盘 ≤ 24h | 100% | 每次 |
| **口令数** | 口令表条目数（能力沉淀量） | 每月 +1~2 | 每月 |
| **成本结构** | 子代理 vs 主模型 token 占比 | 机械活下沉，子代理占比上升 | 每周 |

### 7.2 三个"体检"动作

**① 抽检（每周 1 次，3 分钟）**
> 随机抽 5 条本周的提示词，检查：有没有验收？有没有禁止项？能不能复用？

**② 台账转化率（每周日）**
> 本周台账 N 条 → 其中几条变成了规则/模板？转化率 < 50% = 台账在当抱怨清单用。

**③ 闭卷自测（每月）**
> 不看资料，能否写出 A 型冻结单的五个字段？能 → 已内化；不能 → 回到 §3 复习。

### 7.3 反面信号（出现即预警）

- 连续 2 周没有新增任何模板 → 说明没在用，方案没落地。
- 台账只增不减、从不去看 → 把 §4.4 回流规则重读一遍。
- 还是在"换措辞"而不是"改验收标准" → 犯了教程 §"卡住了怎么办"的原错。
