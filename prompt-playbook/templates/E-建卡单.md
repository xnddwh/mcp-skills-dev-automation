# E 型 · 建卡单

> **用途**：把做过的事变成可复用能力（skill / 台账条目）。

## 模板（复制这一块）

```
【建卡】
素材：<本次做的事 / 用户的合书复述>
落点：<skill Always-on 规则 / 坑列表 / references/ 主题文件>
分类要求：
  ① 规章级 → Always-on 规则
  ② 具体坑 → 坑列表（现象 / 根因 / 判据）
  ③ 状态   → 项目状态文件
禁止：把只写在提交信息里的结论当作已落盘。
```

## 落点分层表

| 内容 | 落点 |
|---|---|
| 跨会话纪律 | skill 的 Always-on 规则 |
| 一次性坑 | skill 坑列表 或 `references/<主题>.md` |
| 项目状态 | 项目内的状态文件（**不写 memory**，会溢出） |
| 用户偏好 | 用户画像文件（精炼） |

## 规范要点

- **名字由用户起**（若涉及总结卡/题型卡等需命名的产物）。
- **"没落盘 = 没学会"**：只写在提交信息、对话里的结论，换会话就丢了。
- 高危遗漏点：**规章级条目最容易被漏**（只写了具体坑，忘了升级为规则）。

## 检查清单

- [ ] 内容是"规章级"还是"具体坑"？分对类了吗？
- [ ] 有没有只写在提交信息里、没落盘的部分？
- [ ] 落点文件是否真实存在？
- [ ] 下次能不能靠一条判据验证它生效？
